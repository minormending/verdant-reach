Contracts and game data

Every module in Verdant Reach speaks one shared language: the ids, data shapes and runtime types in src/contracts/. The game's content (130 plant species, 120 moves, 30 items) lives in plain JSON under src/data/. Small TypeScript loaders check that JSON when the module loads and build one object, DATA: GameData. The battle engine, the menus, the overworld and the strategy guide all read from it.

This section covers that shared language and the data built on it. It also covers the rules that live in the data: how plants grow (evolve), what they learn, how two plants set a seed in the Nursery, and how often a sport (this game's shiny) appears.

"Quickened" is the in-world word for a plant that has woken up and can battle. In code, Quickened is the type of one owned creature (the Pokémon-instance equivalent), and Species is the static description of a kind of plant.

src/contracts: the shared language

Contracts are the types and constant lists that more than one module depends on. They belong to the coordinator ("main") and are treated as frozen: an agent who needs a change asks for it rather than editing the file (ARCHITECTURE.md). Keeping them small and stable is what lets the engine, battle, data, world and art work proceed in parallel.

One list, two uses: as const arrays

Most id lists are written once as a readonly array and the type is derived from it. The array exists at runtime (the loaders use it to validate JSON) and the union type exists at compile time (the compiler rejects a typo like "wod"). Nothing has to be kept in sync by hand.

export const TYPES = [
  "wood", "fire", "water", "bug", "bloom", "ghost", "thorn", "frost", "dragon",
] as const;
export type TypeId = (typeof TYPES)[number];

export const STATUSES = [
  "blight",    // poison-like: chip damage each turn
  "scorch",    // burn-like: chip damage, physical attack halved
  "frostbite", // freeze-like: can't act until thawed
  "dormant",   // sleep-like: can't act for 1-3 turns
  "rootbound", // paralysis-like: speed down, may fail to act
] as const;
export type StatusId = (typeof STATUSES)[number];

Items are the exception. The world and story scripts rely on a fixed set of item ids, so those are listed in REQUIRED_ITEMS, but the data agent may add more without a contract change:

export type RequiredItemId = (typeof REQUIRED_ITEMS)[number];
export type ItemId = RequiredItemId | (string & {});
export type MoveId = string;
export type TrainerId = string;

Advanced: changing a contract safely
  • Adding an id is a contract change; adding content under an existing id is not. The comment at the top of ids.ts says so, and the tests enforce it from the other side: every id in SPECIES_IDS must have exactly one species entry and one Herbarium page, so a new id without data fails npm test straight away.
  • SPECIES_IDS order is load-bearing. The species loader re-orders DATA.species to match it ("so iteration order is stable whatever the file layout"). The Herbarium screen walks SPECIES_IDS directly, and anything iterating DATA.species sees the same order, so where you insert an id is where the species appears in the Herbarium. New species go at the end of their chapter's block.
  • (string & {}) is a TypeScript idiom: it widens ItemId to any string while stopping the compiler from collapsing the union to plain string, so editors still autocomplete the required ids.
  • MoveId and TrainerId are plain strings. Their existence is checked by tests (speciesFiles.test.ts "only uses moves that exist", world/validate.ts for trainers), not by the type system. That is the trade-off for keeping 120 move ids out of the frozen contracts.
  • Some contract comments have fallen behind the code. SPECIES_IDS is still introduced as "The playable roster (Prologue -> Chapter 4)" although it now runs to the post-game, and GrowthTrigger's cross_pollination says "not reachable in slice" although NPC trades now trigger it (growth). Trust the code, not the comment.

Runtime types: Quickened and GameState

A Species never changes during play. A Quickened is one plant you own, and it changes all the time: it gains EXP, takes damage, learns moves. The save file is mostly an array of these.

GameState is the whole save: party (max 6), box (the specimen cabinet), bag (ItemId → qty), story flags, marks (badges), the Herbarium's seen/caught lists, position, the last greenhouse (heal, where a whiteout sends you), options, and the optional nursery. BattleRequest and BattleOutcome are the battle module's input and output; see the battle lifecycle.

Advanced: stored stats and old saves
  • Stats are stored, not derived on read. recalcStats (stats.ts) runs on level-up, on growth and in the Nursery. The save loader (src/save/index.ts) cleans seeds, the Nursery and wanderers, but it does not recompute stats. So a base-stat edit reaches a plant in an existing save at its next level-up or growth, not on load. docs/DATA.md says stats are "computed from its species on load". On this branch that is not what the code does.
  • recalcStats moves current HP by the change in max HP and keeps a healthy plant at 1 HP or more. A wilted plant (hp 0) stays at 0, so growing or levelling never revives one.
  • Optional fields (playerLook, nursery, hallOfFame, seed…) are optional so that older saves still type-check and load. That is why the contract has no version bump: GameState.version is still 1.
  • A Nursery boarder carries an extra boardedLevel (Quickened & { boardedLevel?: number }), and it is deleted when the boarder leaves. Intersection types like this keep side-data off the main contract.

Constants and asset paths

constants.ts fixes the Game Boy Color frame: a 160×144 logical screen (SCREEN_W, SCREEN_H), 16 px tiles, a 10×9 tile view, 60 fps, an 8×8 font and an 18-column × 2-line text box. TIME_OF_DAY sets morning at 4:00, day at 10:00 and night at 18:00 (real clock). The UI palette holds the Crystal-like window and HP-bar colours.

The path helpers build logical asset paths. Code asks for assets/species/oak_acorn/front.png, and the art registry resolves that to whichever bundle or art pack supplies it. The sport colouring is the same path with ?sport:

export const speciesPath = (id: SpeciesId, kind: SpeciesSpriteKind, opts: { sport?: boolean } = {}) =>
  `assets/species/${id}/${kind}.png${opts.sport ? "?sport" : ""}`;

This is why swapping art never touches gameplay data: the JSON refers to species ids, never to files.

Advanced: the balance guard rails in the data tests

data.test.ts holds the cross-species rules the loader can't see:

  • Every stage-1 species has a level-1 attacking move that shares one of its types, so a fresh catch always has a STAB (same-type attack bonus) option.
  • Growth levels increase along a line (stage 2's level is above stage 1's), and the three starters grow at 16 and 32.
  • Stat totals: oak_acorn is pinned at 310, green_chili at 405, giant_water_lily at 525, as fixed reference points. Round-3 two-stage lines sit at 250–320 and 400–470, with learnsets of at least 10 moves reaching level 36 or more.
  • Growth rates on this branch: medium 95, slow 31, fast 4. Moving a whole line to slow means 25% more EXP at every level, which the balance tests won't catch (they build parties at fixed levels).

Then the balance tests (battle tests) re-run boss fights with typical parties, so a stat change that makes a leader too easy or too hard fails before it ships.

Loaders and validation

Each data file has a small loader that does three things:

  1. Import at build time. import.meta.glob("./species/*.json", { eager: true }) for species, plain import file from "./moves.json" for moves and items. Vite inlines the JSON into the bundle, so there is no runtime fetch and no loading state.
  2. Check the shape. A pure function (speciesLineErrors, movesFileErrors, itemsFileErrors) returns a list of human-readable errors, empty when valid.
  3. Fail loudly or build the record. Any error throws at module load, naming the file and field; otherwise the loader builds the Record that goes into DATA.
/** Shape errors for one line file (empty when valid). Cross-file checks are in the data tests. */
export function speciesLineErrors(file: string, d: SpeciesLineFile): string[] {
  const errs: string[] = [];
  const at = (where: string, msg: string) => errs.push(`${file}: ${where}: ${msg}`);
  const isInt = (n: unknown) => typeof n === "number" && Number.isInteger(n);
  if (d.format !== "verdant.speciesline/2") at("format", `expected "verdant.speciesline/2"`);
  if (`${d.line}.json` !== file) at("line", `must match the file name (${file})`);
  // …
  for (const [i, s] of (d.species ?? []).entries()) {
    const w = `species[${i}] ${s.id ?? "?"}`;
    if (!(SPECIES_IDS as readonly string[]).includes(s.id)) at(w, "id is not in SPECIES_IDS (src/contracts/ids.ts)");
    // …
    for (const k of STAT_KEYS) if (!isInt(s.baseStats?.[k]) || s.baseStats[k] < 1 || s.baseStats[k] > 255) at(w, `baseStats.${k} must be an integer 1-255`);
    // …
  }
  return errs;
}

A typo produces a message like oak.json: species[0] oak_acorn: baseStats.hp must be an integer 1-255. Because the check is a pure function that takes the parsed file, the tests can call it on a deliberately broken copy and assert on the messages (speciesFiles.test.ts, "reports mistakes with the file and field").

Advanced: what the loader deliberately does not check
  • Shape, not references. The species loader doesn't check that learnset moves exist in moves.json, or that growsInto stays inside the line. Those are cross-file facts, and they live in tests, which keeps each loader independent of the others' load order.
  • Failing at import is intentional. A bad file throws during module evaluation, so the whole game refuses to start in dev and the build's tests fail. The alternative (skip the bad species) would surface later as a battle against a fallback "Wood, 50 in every stat" plant from lookup.ts, which is much harder to trace.
  • The runtime type drops two fields. fact and source are required in the JSON but not copied into HerbariumEntry; they exist for review and tests. The source check is the unanchored regex /https?:\/\//, so it proves a URL is present, not that it supports the fact. Checking the fact is a human review step.
  • Error lists, not first-error. Each function collects every problem, so one run of the tests shows all mistakes in a file at once.
  • Length limits differ slightly between the contract comments and the loaders (the Item type says "<= 12 chars", the item loader allows 13). The loader is what is enforced.
  • Adding a field to the JSON means adding it in three places: the SpeciesLineFile interface, the mapping in load() and (if shared) the Species contract. Forgetting the mapping step drops the field silently.

Moves: moves.json

One list, one move per line, in order. Later chapters append, so keep new moves at the end. On this branch there are 120 moves: 39 physical, 42 special and 39 status. Physical moves use Attack against Defence; special moves use Special Attack against Special Defence. The split is per move, not per type (an updated mechanic over Crystal).

Advanced: item edge cases
  • itemHasEffect is the single "would this do anything?" check. applyItem calls it first, so field and battle use give the same "It won't have any effect." answer, and a seed always refuses.
  • restore_pp with amount: 0 means "restore fully" (e.amount > 0 ? … : max).
  • The bag caps a stack at 99 (addItem) and deletes the key when a count reaches 0, so bag[id] being present means you own at least one.
  • cold_snap is both a move id (it sets frost) and an item id (it grows Snowdrop Bulb). Moves and items are separate records, so nothing collides, but searching the codebase for the id finds both.
  • Price 0 means it can't be bought or sold. Shops list stock explicitly, so price alone never puts an item on sale.

Herbarium pages and sourced facts

The Field Herbarium is the in-game encyclopedia (the Pokédex equivalent). Every page sits next to its species in the line file. The project's binding rule is that every entry contains one true, checkable fact about the real plant, stated plainly in fact and backed by a source URL. Heights and weights are real ballparks for that growth stage. Medicinal and cultural claims are not allowed.

flowchart LR
  W["Write entry: 2-4 short sentences"] --> F["State the one fact plainly in 'fact'"]
  F --> S["Cite a URL that checks it in 'source'"]
  S --> L{"Loader: fact, entry, names non-empty, source has http(s), height/weight positive"}
  L -- fail --> E["Error names file + species"]
  L -- pass --> T{"Test: DATA.herbarium entry matches the file, every SPECIES_ID has a page"}
  T --> R["Human review: does the source say it?"]

At runtime only the display fields reach DATA.herbarium: scientific name, category, height, weight and entry. The Herbarium screen, the post-catch page and the guide all render from that record.

Growth triggers

Growth is this game's word for evolution. A species may name its next stage with growsInto and a trigger. The triggers mirror Gen 2's evolution methods with plant names:

export type GrowthTrigger =
  | { kind: "vigor"; level: number }                     // level up
  | { kind: "vigor_day"; level: number }                 // level up during morning/day
  | { kind: "vigor_night"; level: number }               // level up at night
  | { kind: "tending"; friendship: number }              // friendship >= value on level up
  | { kind: "item"; item: ItemId }                       // use item from the bag

export function growthTarget(data: GameData, q: Quickened, time: TimeOfDay): SpeciesId | null {
  if (q.seed) return null;
  const g = getSpecies(data, q.species).growsInto;
  if (!g || !data.species[g.species]) return null;
  const t = g.trigger;
  switch (t.kind) {
    case "vigor": return q.level >= t.level ? g.species : null;
    case "vigor_day": return q.level >= t.level && time !== "night" ? g.species : null;
    case "vigor_night": return q.level >= t.level && time === "night" ? g.species : null;
    case "tending": return q.friendship >= t.friendship ? g.species : null;
    default: return null;
  }
}

Advanced: growth timing rules and their edge cases
  • Only plants that levelled are checked. The scene keeps a leveled set of uids. A plant already past its growth level (a trade, a cancelled growth) grows at its next level-up in battle, not at the next battle.
  • "Day" includes morning. vigor_day passes for any time except night (4:00–18:00 on the real clock). The time is read again at the battle's end with worldTime, not taken from when the battle started.
  • tending has no level requirement, but it is only checked after a battle level-up. Friendship rises +5/+3/+2 per level (below 100 / below 200 / above), and falls 1 when your plant wilts.
  • No growth after a loss, and wilted plants never grow. Nursery boarders level up there but never grow (boarderExp skips the check), as in Gen 2's Day Care.
  • growthTarget also returns null if the target species is missing from DATA. This keeps a half-added line from crashing.
  • Item growth is checked through canGrowWith, which the party screen also uses to show Crystal's ABLE / NOT ABLE label. isGrowthItem recognises growth items even when nobody in the party can use them.

EXP curves and learnsets

Each species has a growth rate that picks one of three Gen 2 EXP curves. expForLevel returns the total EXP needed to reach a level:

// Gen 2 experience curves. Our three rates map to:
//   fast   -> Gen 2 "fast"        4n^3 / 5
//   medium -> Gen 2 "medium fast" n^3
//   slow   -> Gen 2 "slow"        5n^3 / 4
// Level 1 always needs 0 exp. Capped at level 100.
export function expForLevel(rate: Species["growthRate"], level: number): number {
  const n = Math.max(1, Math.min(100, Math.floor(level)));
  if (n <= 1) return 0;
  const cube = n * n * n;
  switch (rate) {
    case "fast": return Math.floor((4 * cube) / 5);
    case "medium": return cube;
    case "slow": return Math.floor((5 * cube) / 4);
  }
}

A learnset is a list of [level, move] pairs. Level-1 entries are the starting moves. When a Quickened is created at some level (a wild plant, a trainer's plant), it knows the moves it would have learned by then:

export function movesAtLevel(species: Species, level: number, isAttack?: (id: MoveId) => boolean): MoveId[] {
  const learned: MoveId[] = [];
  const entries = species.learnset
    .map((e, i) => ({ ...e, i }))
    .filter((e) => e.level <= level)
    .sort((a, b) => a.level - b.level || a.i - b.i);
  for (const e of entries) {
    const at = learned.indexOf(e.move);
    if (at >= 0) learned.splice(at, 1);
    learned.push(e.move);
  }
  const chosen = learned.slice(-4);
  // … keeps at least two attacking moves when it has learned them
  return chosen;
}

This is Gen 2's "last four moves learned" with one change: if the last four would leave fewer than two attacking moves, it swaps the oldest status move for the most recent older attack. Status-heavy learnsets would otherwise give wild and trainer plants a single attack, which no human player would choose.

Your own plants learn one level at a time instead: movesLearnedAt(species, level) lists the moves for exactly that level, and the learn flow offers each one (see level-up).

Stats, DVs and EV yields

Stats follow the Gen 2 formula, with EVs stored on the modern 0–252 scale:

//   HP    = floor(((Base + IV) * 2 + floor(EV / 4)) * L / 100) + L + 10
//   Other = floor(((Base + IV) * 2 + floor(EV / 4)) * L / 100) + 5
export function calcStat(key: StatKey, base: number, iv: number, ev: number, level: number): number {
  const core = Math.floor((((base + iv) * 2 + Math.floor(ev / 4)) * level) / 100);
  return key === "hp" ? core + level + 10 : core + 5;
}

Worked example: an Oak Acorn (base HP 52) at level 5 with an HP DV of 8 and no EVs has floor((60 × 2) × 5 / 100) + 5 + 10 = 6 + 15 = 21 HP.

DVs are rolled 0–15 for Attack, Defence, Speed and Special. Special Attack and Special Defence share the Special DV, and the HP DV is assembled from the low bit of each of the other four, exactly as on the Game Boy. Trainers' plants use the fixed Gen 2 trainer DVs 9/8/8/8.

EV yield (evYield) is what a species gives when defeated. On this branch all 130 species declare one: 49 give 1 point, 49 give 2 and 32 give 3. gainEvs adds it up to the 252 per stat and 510 total caps.

Advanced: EV and DV details
  • If a species had no evYield, gainEvs would give +1 in its highest base stat (the first in hp, atk, def, spa, spd, spe order on a tie). No species relies on that fallback today.
  • EVs are given to every plant that receives an EXP share, including those that sat out (awardExp calls gainEvs before checking participant). That is Gen 2's EXP Share behaviour applied to the whole team.
  • floor(EV / 4) at 252 EVs adds 63 to the core, the same maximum Gen 2's floor(ceil(sqrt(statExp)) / 4) produced. At level 100 that is +63 to the stat; at level 50, +31.
  • Because the HP DV is derived, any code that changes DVs (the Nursery's inheritIvs) must rebuild hp from the low bits too, or HP would disagree with the other four.

The rules, from src/overworld/nursery.ts (pure logic, unit-tested; the counter dialogue is in nurseryFlow.ts):

  • Up to 2 boarders. Each gains 1 EXP per player step and can level up, but learns no moves and never grows.
  • Taking one back costs $100 plus $100 per level gained. The party must always keep one healthy non-seed plant.
  • Every 256 steps, if both boarders share a group: 50% chance of a seed for the same line, 20% for a shared group.
/** Seed chance per 256-step check: 0.5 same line, 0.2 shared group, else 0. */
export function compatibility(data: GameData, a: Quickened | undefined, b: Quickened | undefined): number {
  if (!a || !b) return 0;
  const sa = data.species[a.species];
  const sb = data.species[b.species];
  const ga = sa?.pollination ?? [];
  const gb = sb?.pollination ?? [];
  if (!ga.length || !gb.length || !ga.some((g) => gb.includes(g))) return 0;
  return sa.line === sb.line ? 0.5 : 0.2;
}

  • Species: the stage-1 species of the first-boarded parent's line, at level 5.

Advanced: Nursery odds and invariants
  • Expected wait. Checks happen only every 256 steps, so the expected wait for a seed is 256 / 0.5 = 512 steps for a same-line pair and 256 / 0.2 = 1,280 steps for a shared-group pair.
  • seedReady blocks further checks: there is at most one uncollected seed. The step counter still resets every 256 steps.
  • Order matters. slots[0] is the seed parent. Swapping who boards first changes the species of the seed when the parents are from different lines.
  • stage1Of looks for the line's stage === 1 species first and falls back to walking growsInto backwards (at most 4 hops), so a line file with a missing stage 1 still yields a sensible seed.
  • makeSeed calls createQuickened, which consumes one 1/512 sport roll from the RNG, then overwrites sport with the 1/256 roll. With a seeded RNG, adding or removing a random call here changes every later draw, so it shows up in seeded e2e replays.
  • Boarders' EXP is capped at the level-100 total, and levelsGained never goes negative, so the fee is always at least $100.
  • A seed can't battle (canFight excludes it), gets no EXP share, and qName shows "SEED" so the species stays a surprise.

Sports (shinies) and their odds

A sport is a real horticultural term: a plant shoot with a natural mutation, often a new colour. In Verdant Reach it is the shiny. The odds live in stats.ts:

The chance of at least one sport in n tries is 1 − (511/512)n. A sport changes only colour: its art is an exact swap of palette indexes 1–2 to the bundle's sport palette, each based on a real cultivar (docs/SPORTS.md). Stats are unaffected, unlike Gen 2, where shininess was tied to DVs.

Advanced: sports and determinism
  • Sport is an independent roll, not derived from DVs, so it can't be inferred from stats and doesn't constrain them. The trade-off: there's no way to reproduce Gen 2's "shiny breeding" tricks, which is intended.
  • The roll is made after the DVs and before the uid in createQuickened. Seeded runs (?seed=N, npm run e2e -- --seed N) reproduce sports exactly; reordering those calls changes which encounter is a sport.
  • The battle scene plays a sparkle when a sport is sent out and passes { sport } to every species draw call; the Art Lab's sport toggle previews the palette without a battle.
