The art system

Every picture in Verdant Reach (each creature, tile, building, walking character, portrait, item icon and story still) lives under public/art/ as a bundle: a folder holding one JSON file and the PNGs it names. Game code never opens those files directly. It asks for a logical path such as assets/species/oak_acorn/front.png, and the art registry (registry.ts) works out which file, which part of it and which colours to hand back.

Why the extra step? It means the art can be swapped without touching code. You can replace a folder, turn on an art pack that overrides some bundles (?art=classic), or patch a bundle in memory in the Art Lab, and the game, the guidebook and the Tile Lab all see the change. The format is the contract between three groups: the TypeScript runtime, the Python generators in tools/art/, and anyone who edits a PNG by hand.

There is no build step for art. The browser reads bundles straight from public/art/, so you can redraw a PNG, reload the page and see it in the game. The one thing that needs a command is adding, removing or renaming a file: run npm run art:index afterwards (below).

A species bundle

Here is the real Venus flytrap bundle, public/art/species/venus_flytrap/species.json (credits and notes shortened):

{
  "format": "verdant.species/1",
  "id": "venus_flytrap",
  "palette": ["#181818", "#a82838", "#90d048", "#f8f8f8"],
  "sport": ["#181818", "#601830", "#d83840", "#f8f8f8"],
  "frames": {
    "front": ["front.png", "front__2.png", "front__3.png", "front__4.png", "front__5.png", "front__6.png"],
    "back": ["back.png"],
    "icon": ["icon.png", "icon__2.png"]
  },
  "anim": { "intro": [[0, 6], [1, 6], [2, 20], [3, 4], [4, 5], [3, 4], [4, 5], [3, 8], [5, 6], [0, 2]], "idle": [[0, 120], [1, 10]] },
  "credits": "Original pixel art for Verdant Reach, hand-pixelled in tools/art/crystal/flytrap.py. …",
  "source": { "kind": "generated", "tool": "tools/art/crystal/flytrap.py" },
  "notes": "Gesture: the jaws gape, gape wider, HOLD (20 ticks), SNAP shut … Sport: 'Akai Ryu'."
}
  • Indexed colour. palette has exactly 4 colours, darkest first. Every opaque pixel in every frame must be one of them, and alpha is only 0 or 255. This rule is what makes recolours and sports possible: a pixel's colour is its palette index.
  • sport is the shiny palette. Rendering a sport replaces palette[i] with sport[i] pixel for pixel, so a sport needs no extra images.
  • anim lists [frame, ticks] steps at 60 fps. The flytrap's intro adds up to 66 ticks (1.1 s) and ends on frame 0.
  • source says where the pixels came from. A generated bundle may be rewritten by its tool; an edited or imported one never is.

A tileset bundle

A tileset is one sheet PNG cut into 16px cells, numbered left to right, top to bottom. Cell n is at x = (n % columns) * 16, y = floor(n / columns) * 16. The tiles map gives each TileKey a ref: one cell number (a still tile) or a list of 1–2 cells (animation frames 1 and 2). From public/art/tilesets/terrain/tileset.json:

{
  "format": "verdant.tileset/1",
  "id": "terrain",
  "name": "Terrain",
  "tileSize": 16,
  "sheet": "sheet.png",
  "columns": 16,
  "tiles": {
    "grass": { "base": 0, "alts": [1, 2, 3] },
    "flowers": { "base": [4, 5] },
    "tall_grass": {
      "base": [16, 17],
      "masks": {
        "0": [32, 48],
        "1": [33, 49],
        …
  • alts (up to 3) are ground variations, picked per cell by a position hash so a field of grass doesn't look stamped.
  • masks are autotile variants keyed "0"–"15". Each bit says a same-group neighbour is present: N=1, E=2, S=4, W=8. Mask 5 (N+S) is a vertical run, mask 15 is fully surrounded. A missing mask falls back to base.
  • Which tiles join which group is gameplay, so it stays in AUTOTILE in the contracts. A tileset only supplies pictures.
flowchart LR
  N["N neighbour = 1"] --> M["mask = N + E + S + W"]
  E["E neighbour = 2"] --> M
  S["S neighbour = 4"] --> M
  W["W neighbour = 8"] --> M
  M --> L["look up tiles.key.masks[mask]"]
  L -->|"missing"| B["use base"]

Structures, characters and image sets

  "rows": ["down", "up", "left", "right"], "columns": ["stand", "stepA", "stepB"], … }

{ "format": "verdant.imageset/1", "id": "items", "logicalDir": "assets/items",
  "images": { "aloe_gel": { "file": "aloe_gel.png", "size": [16, 16], "source": { "kind": "generated", "tool": "tools/art/cast4/items4.py" } }, … } }

An image set maps a whole logical directory to one bundle: portraits serves assets/trainers, items serves assets/items, ui serves assets/ui and stills serves assets/stills. Each entry may carry its own source, so a generator can skip one hand-edited icon in a set it otherwise owns.

Advanced: format invariants and how to extend them
  • Each TileKey has exactly one owner. The catalog indexes tile owners by scanning tilesets in id order and keeping the first, but validateArt reports a duplicate as an error, so in practice ownership is unique. Group keys by theme (terrain, nature, town, city…) so a pack can swap a whole look at once.
  • Forward compatibility. Readers ignore fields they don't know, and writers may add optional ones. Renaming or repurposing a field needs a new format version (verdant.species/2), because old readers would silently misread it.
  • File names are free. The JSON names every file, so front.png is only the default tools write. Logical paths never depend on file names, only on ids and frame kinds.
  • Animated masks. If base has 2 frames, every mask should too. refCells(ref)[frame - 1] returns undefined for a missing second frame, and the path then fails to resolve, so the renderer falls back down its chain (see required art).
  • Unparseable JSON provides nothing. The catalog drops a bundle whose JSON isn't an object; the validator is what reports it. A typo in one bundle therefore shows up as missing art plus a test failure, not a crash.

The index (npm run art:index)

A browser cannot list a directory over HTTP. So that the registry knows which bundles exist and which files each folder holds, tools/art/index.mjs (Node, zero dependencies) scans public/art/ and writes public/art/index.json:

{
  "format": "verdant.artindex/1",
  "species":    { "<id>": ["front.png", ...] },
  "tilesets":   { ... }, "structures": { ... }, "characters": { ... }, "sets": { ... },
  "packs": { "<pack_id>": { "name", "description", "author", "species": { ... }, ... } },
  "legacy": ["assets/tiles/grass.png", ...]
}

The index lists file names, not JSON contents. The registry fetches every bundle JSON itself. That gives a simple rule:

Advanced: staleness, stray folders and the no-index mode
  • src/art/bundles.test.ts rebuilds the index in memory with buildIndex() and compares it to the file on disk, so a forgotten art:index fails npm test. node tools/art/index.mjs --check does the same from the shell.
  • strayFolders() finds folders under a kind directory with no bundle JSON. They are not indexed (the runtime would never see them), the script warns, and a test requires the list to be empty.
  • formatIndex() writes one line per bundle in sorted order, so a diff of index.json shows exactly which bundles gained or lost files.
  • If index.json can't be loaded, the registry logs a warning and sets indexLoaded = false. The catalog is built with legacy: null, which means "try every unowned assets/… path as a plain file". That is the Round 4 migration fallback. public/assets/ has since been deleted and legacy is empty, but the code path remains, so a broken index degrades to missing art rather than a crash.

Layers and the shallow merge

ArtCatalog is pure: no DOM and no Node, so the game, the Art Lab and the Node bundle test all share it. It groups every raw bundle by kind/id into a stack of layers, bottom-up:

flowchart BT
  L0["Layer 0: base bundle (public/art/species/oak_acorn/)"] --> L1["Layer 1: first active pack"]
  L1 --> L2["Layer 2: later pack (wins)"]
  L2 --> LAB["Top: @lab (in-memory JSON patch)"]
  LAB --> MG["merged JSON (what the game sees)"]

Packs are ordered by their position in the active list, so in ?art=a,b pack b wins. The merge is shallow: a higher layer's top-level field replaces the lower one outright. Tilesets' tiles and sets' images are merged one level deeper, which is what lets a pack override a single tile or a single icon:

/** Merge one layer's JSON over the accumulated JSON. */
function mergeJson(kind: BundleKind, under: Record<string, unknown>, over: Record<string, unknown>): Record<string, unknown> {
  const out: Record<string, unknown> = { ...under, ...over };
  const deep = kind === "tilesets" ? "tiles" : kind === "sets" ? "images" : null;
  if (deep && isObj(under[deep]) && isObj(over[deep])) out[deep] = { ...(under[deep] as object), ...(over[deep] as object) };
  return out;
}

JSON merges, but files resolve separately: findFile walks from the top layer down and takes the first layer whose folder (as listed in the index) holds that file name. A pack that ships only front.png replaces that one frame and reads the rest from the base folder.

Two caches make this cheap enough to call every frame. The catalog memoises resolve(path), and the registry keeps derived, the finished canvas per path. Both are thrown away whenever packs or overrides change (rebuild() makes a new catalog and bumps version).

Single-tile versus whole-sheet overrides

A tileset pack can do two different things, and the catalog tells them apart by whether the pack's JSON defines its own tiles:

flowchart TD
  K["tile key, defined last at layer d"] --> UP{"a layer above d without its own tiles has the sheet file?"}
  UP -->|"yes"| WHOLE["read that sheet (whole-sheet swap)"]
  UP -->|"no"| DOWN["findFile from d downward"]
  DOWN --> SPARSE["the defining layer's own sheet (single-tile override)"]
  • Single-tile override. The pack's tileset.json has "tiles": { "grass": { … } } and its own small sheet.png. Thanks to the deep merge only grass changes; its cells are numbered in the pack's sheet, while every other key keeps reading the base sheet.
  • Whole-sheet swap. The pack ships sheet.png with a tileset.json that does not define tiles. Every key keeps its base cell numbers but reads them from the pack's sheet, so the new sheet must use the same layout.

Palette-only recolours and sports

A species image is drawn in the palette of the layer it came from. resolveSpecies builds a Recolor from that layer's palette to the merged palette, or to sport for a ?sport path. makeRecolor returns null when the two match, so ordinary frames are never copied:

const f = this.findFile(v, name);
const recolor = makeRecolor(this.paletteAt(v, f.layer), target) ?? undefined;

Hence a palette-only pack: a pack species JSON with a new palette and no frames recolours the base images index by index. The traced pack does this for red_chili; its folder holds only species.json.

Advanced: resolver edge cases
  • Shallow means whole fields. A pack that sets frames replaces all three lists, not just front. A pack whose art predates the base's anim must set "anim": null, or the base intro would index frames the pack doesn't have. The classic pack does this for every species.
  • A tile key's definition is replaced whole. The deep merge stops at tiles.<key>: a pack that overrides grass must restate its alts and masks, or they vanish. The Tile Lab's planner copies untouched alts and masks in for exactly this reason.
  • Geometry follows the sheet. columns and tileSize are read at max(d, sheet layer), so a whole-sheet pack may also change columns.
  • Sports need matching lengths. If sport is missing or a different length from palette, a ?sport path resolves to null (missing), not to the normal colours. Sports never fall back to legacy files.
  • listed: false means no layer's index entry holds the file. The resolution still points at the lowest real layer's folder, where the file will probably 404. The Tile Lab relies on this: it registers an in-memory override at exactly that URL (see the Tile Lab).
  • The @lab layer has no files. findFile skips it, so lab patches change JSON only, and file swaps go through overrideFile(url) in the registry.
  • Recolouring is exact. recolorRgba maps whole RGB values and skips alpha 0. A pixel that isn't one of the palette colours is left alone. The validator forbids such pixels, but if one slips through it shows up as a stray dot in sports.

Required art and placeholders

required.ts lists every logical path the contracts need: a front, back and icon for each id in SPECIES_IDS, every TILES key (plus frame 2 of water, tall_grass and flowers), every structure, character, trainer portrait, required item icon, Pressed Mark, UI image and still, each with its expected size. bundles.test.ts fails, grouped by kind, if any of them doesn't resolve at the right size.

That raises a problem: you can't add a new species id until its art exists, and its art might take days. The answer is placeholder.py. It writes a grey blob with a "?" in the Crystal palette, with notes starting PLACEHOLDER (set images are marked by tool: tools/art/placeholder.py). release-check then refuses both markers anywhere in public/art/:

At runtime, missing art never crashes the game. Each drawer has a fallback. drawCell in tilelayer.ts tries the variant path, then the plain key, then draws a hand-coded stand-in tile with a magenta corner pip. Trainer portraits fall back to a drawn placeholder and log one warning per path.

Advanced: "pending" versus "missing"

image(path) returns undefined both while a PNG is still loading and when it will never exist. Renderers that care ask isMissing(path): true only once the path is known not to resolve, or its file failed to load (and isn't overridden). The tile layer uses that to tell "draw a fallback and keep it" from "draw a fallback now, but redraw this cell when the file arrives". If it treated pending as missing, the first frames after boot would bake placeholders into the cached tile layer.

The Crystal creature rules

Every creature is drawn under the Crystal rule (docs/CREATURES.md), named after the Game Boy Color game whose sprite discipline it borrows. The pre-Crystal art is kept as the classic pack. These rules bind every species, and tools/art/crystal/kit.py checks them:

IndexRoleColour
0the full outline, deepest crevices, seams, cast shadowalways #181818
1the species' dark tone: shading and a second hue (the flytrap's trap red)species' choice
2the species' light tone: usually most of the bodyspecies' choice
3highlights onlyalways #f8f8f8
  • A full black outline, no selout. A colour pixel touching transparency is an outline gap.
  • White share: 5–20% of a front (backs and icons at least 3%). Approved WHITE_PARTS (white clover, moonflower, the dandelion clock, chili blossom, giant water lily) may reach 35%. EXCEPTIONS (the sunflower line) keep a gold third hue in index 3. Both need a reason in notes.
  • The sport swaps only indexes 1–2 and is based on a real cultivar.
  • No faces. Plants never get eyes or mouths. A black dot with a white glint reads as an eye, and a dark slit reads as a mouth, so check every frame at 1x.
  • Never copy, trace or import a Nintendo or Game Freak sprite.

The entrance animation

Every species has an anim.intro of 3–6 front frames lasting 36–72 ticks and ending on frame 0, in which only its signature part moves (the flytrap snaps, the fern uncurls). An optional idle holds frame 0 for 90–150 ticks, then twitches. anim.ts turns "ticks since the creature appeared" into a frame:

stateDiagram-v2
  [*] --> intro: appears
  intro --> idle: t reaches intro length
  intro --> hold: no idle
  idle --> idle: loop
  hold --> hold: frame 0
  note right of intro: frame and ticks steps at 60 fps
export function animState(anim: SpeciesAnim, t: number, opts: { intro?: boolean } = {}): AnimState {
  const tt = Math.max(0, Math.floor(t));
  const introLen = opts.intro ? stepsLength(anim.intro) : 0;
  if (anim.intro && tt < introLen) {
    const step = stepAt(anim.intro, tt);
    return { phase: "intro", frame: anim.intro[step][0], step };
  }
  const idleLen = stepsLength(anim.idle);
  if (anim.idle && idleLen > 0) {
    const step = stepAt(anim.idle, (tt - introLen) % idleLen);
    return { phase: "idle", frame: anim.idle[step][0], step };
  }
  return { phase: "hold", frame: 0, step: -1 };
}
Advanced: validator versus runtime, and the moving boxes
  • Two views of anim. checkSpeciesAnim (used by the validator) reports every malformed step. parseSpeciesAnim (used at runtime) drops bad steps and appends [0, 1] if an intro doesn't end on frame 0, so a bad bundle fails the tests but still plays in the game.
  • Any anim object opts out of the legacy ping-pong. Even {} just holds frame 0; only undefined or null brings back the old "first ≤3 frames ping-pong" idle.
  • Moving boxes. write_species(moving=[…]) records end-exclusive boxes in tools/art/crystal/moving/<id>.json. The kit checks that frames differ only inside them, and QA's anim_signature warns when under 80% of changed pixels fall inside them. That is what "only the signature part moves" means in practice.
  • The 56x56 box must fit the largest frame. If the flared frame clips, shrink frame 0, not the gesture.

Why --regen must leave git clean

A regen reproduces every generated bundle byte for byte. If it changes a file you didn't mean to change, either a generator isn't deterministic or someone hand-edited a generated bundle without marking it edited. Three mechanisms make this hold:

def save_png(path: Path | str, img: Image.Image | np.ndarray) -> Path:
    """Write an RGBA PNG (colour type 6, no metadata). Only rewrites the file
    when the bytes differ, so mtimes stay put on a no-op regen."""
    p = Path(path)
    data = png_bytes(to_rgba(img))
    if p.exists() and p.read_bytes() == data:
        return p

  • PNGs carry no metadata (no timestamps) and JSON is formatted stably.
  • emit skips any bundle or set entry whose source.kind is edited or imported, and keeps hand-kept metadata (sport, credits, notes).
  • The libraries are pinned, so the same drawing code gives the same bytes on any machine.

QA: the kit checker, qa:art and qa:maps

  • crystal/kit.py is the rule checker: 4-colour palettes, black and white in indexes 0 and 3, sport ≠ palette, frame sizes and counts, white share, outline gaps, orphans, intro length (36–72) and moving boxes. Errors must be 0.
  • npm run qa:art (tools/art/qa/qa.py) adds heuristics: face_risk, size_class, stage_progression, clone_risk (perceptual hashes), tile seam, autotile_edges and grid_artifact. It never writes art. npm run qa:art:changed (--all --changed origin/main) is the gate: only changed bundles can fail it.
  • npm run qa:maps (Vitest, tools/art/qa/maps.ts) measures, for every standable tile on every outdoor map, whether the 10x9 camera view contains a landmark. Towns warn below 85%, other routes below 60%.
Advanced: builder order, process isolation and the QA baseline
  • Order is data. Some builders read shipped art: characters runs after tiles because the hedge gate samples the hedge tile, env8 recolours water, and env9 draws props over wall, cable_floor and paving. The comments in BUILDERS say why; keep them when you add a line.
  • One interpreter per creature line. crystal/build.py runs each line's build() in its own Python process, because the archived species_a–species_f folders reuse module names like kit and oak. Never sys.path.insert a species_* folder; old shape code loads through kit.legacy("species_x/file.py").
  • Missing versus error. build_all.py rebuilds the index and fails on validation errors. Required paths nobody provides yet only fail with --strict; the TypeScript bundle test is the stricter gate.
  • The QA baseline is red on purpose. The shipped roster predates the QA thresholds (45 size_class failures at calibration). --all exits 0 regardless, so the report stays visible without blocking unrelated work. Don't relax a threshold to make it green.

The Art Lab (?dev=art)

The Art Lab is a full-window DOM tool mounted over the game canvas. It is a dev scene: src/main.ts finds src/art/dev.ts through import.meta.glob("./*/dev.ts") and loads it only when the URL says ?dev=art. It works in production builds too.

Advanced: what the lab's validation can and can't see
  • registry.validate() loads every listed PNG and runs the same validateArt as the Node test, minus the index-versus-folder check (a browser can't list folders).
  • Lab JSON patches count, except a species palette patch. That is a live recolour of unchanged pixels, so it is validated as the original pixels with the original palette.
  • The Compare tab uses fork() and ignores the pack toggles, so "base versus classic" stays meaningful whatever is switched on.
  • The lab exposes window.__artLab = { lab, reg } for poking around from the console.
